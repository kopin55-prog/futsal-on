- 운영진 내보내기·탈퇴 후 기록·추가 알림(Q-015, Q-018, Q-022): 4장 확정
- 초대·가입(Q-002, Q-020, Q-021): 5장 BLOCKED 해제. J-01~J-05 작성. 팀 식별코드(가입코드) 부분은 **Q-029 재질문 중**이라 J-06~J-08 자리만 두고 BLOCKED

- 해결된 미정 번호는 맨 아래 "해결된 미정" 표에 남겨 추적한다. 삭제한 시나리오 번호는 다시 쓰지 않는다.

## 읽는 법

- **유형**: 정상 / 경계 / 권한(다른 역할·다른 팀·비로그인 사용자가 시도) / 예외
- **대응**: 아래 완료 기준 코드. 완료 기준에 없는 규칙은 `기준 외(근거)`로 적는다. 결정 기록이 근거면 질문 번호(Q-xxx)를 함께 적는다.
- **기대 동작 미정**: 기획서·결정 기록으로 정답이 정해지지 않은 부분. 자리만 두고 정답을 적지 않았다. lead 확인 전에는 통과·실패를 판정하지 않는다.
- **권한 시나리오는 두 경로로 확인한다**: (1) 앱 화면에서 버튼이 보이지 않는지, (2) 화면을 거치지 않고 Supabase API를 직접 호출해도 서버가 거부하는지 (security.md "화면에서 숨긴 기능이라도 서버에서 권한을 다시 확인한다").
- **글자 수 규칙(Q-012)**: 이 문서의 모든 "n자"는 눈에 보이는 글자 단위(이모지 하나 = 1자, 결합 이모지·국기도 1자), 앞뒤 공백 제외, 가운데 공백은 1자로 센다. 줄바꿈은 입력할 수 없다. 앱과 서버가 같은 기준으로 세야 한다.
- **알림 시나리오**: 알림 발송은 스프린트 02 작업이다. 이 문서의 알림 항목은 "알림 대상이 맞게 정해지는지"까지만 확인하고, 실제 발송은 스프린트 02에서 확인한다.

## 5. 초대 링크·초대 코드·팀 검색·가입 신청·승인/거절 (기획서 7장, Q-002, Q-020, Q-021)

Q-002 답변으로 BLOCKED 해제. 설치 후 이어서 가입은 "링크 페이지에서 초대 코드 복사 → 앱 첫 실행 때 붙여넣기" 방식(유료 딥링크 서비스 없음). 단 **팀 식별코드(가입코드)는 Q-029 재질문 중**이라 5-1의 J-06~J-08은 자리만 두고 BLOCKED.
초대 링크 규칙(Q-020): 팀당 유효한 링크 1개, 재발급하면 이전 링크 무효, 24시간 안 여러 명 사용 가능, 만료는 신청을 낸 시각 기준, 원본 미저장(다시 복사하려면 재발급). 초대 코드는 그 링크 페이지에 표시되는 값이므로 링크와 함께 유효·무효가 된다고 보고 시나리오를 적었다 (다르면 lead 확인 필요).
