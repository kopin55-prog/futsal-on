## 범위 판단 (planner)
- **부상은 서버를 먼저**(1단계): 표 2개 + 서버 함수(동의 나중에·철회, 등록·연장·회복) + `is_injured_at` 교체 + 참석 투표 시 복귀 + 복귀 확인 알림. 미투표 알림 부상자 제외와 참여율 "부상 중이면 응답"은 `is_injured_at`만 바꾸면 자동으로 동작한다(새로 만들지 않음, 회귀 테스트만).
- **부상 동의 나중에·철회는 01에서 미룬 항목**: 문구는 docs/consent-texts.md 그대로(확정, Q-057). 철회 확인 창 등 새 화면 문구는 Q-067 0번(임시 문구 → 묶음 테스트 때 일괄 수정).
- **"남은 W"는 저장하지 않고 화면에서 계산**(8-2 `expected_return_on`). 계산 규칙(올림/내림)은 S4-04.
- **내 기록은 읽기 함수 하나**(7-2): 시즌별 카운트(7-3) + 참석 투표 참여율(7-7)을 본인 것만, 팀별·시즌별로. 떠난 팀·해체된 팀 포함. 퍼센트는 소수점 없이 반올림(Q-064), 대상 0회면 "기록 없음"(7-7).
- **대시보드는 새 표 없이** 기존 표(일정·참석 응답·배치·수상자·부상·가입 신청)에서 읽는다. 읽기 범위는 기존 권한 규칙 그대로(팀원은 확정 배치만, 부상은 진행 중인 것만, 가입 신청 수는 관리자만). 한 번에 읽는 서버 함수를 둘지는 builder 판단.
- **탭 순서**: 기획서(홈·일정·팀원·내 기록 + 관리)와 Q-074("일정 탭이 첫 탭", 홈이 없던 때 결정)가 부딪힘 → S4-01. 답 전에는 탭 순서를 바꾸지 않는다(4-7 BLOCKED).
- **2차 대비만 하고 숨김**: 관리 탭 "출석·참여 리포트" 메뉴 자리(entitlements `TeamReportInfo` 거절), 내 기록에 득표수 없음. 2차 리포트용 부상 이력 읽기 함수는 만들지 않는다.
- **iOS는 유료 애플 계정 없이 할 수 있는 데까지만**(Q-005-2): 번들 ID 확정(S4-15) → 카카오·구글 iOS 설정, Firebase iOS 앱, 애플 로그인 코드(꺼둠), 클라우드 빌드(S4-16) 서명 없는 빌드 확인. APNs 키 등록·애플 로그인 실제 동작·TestFlight 업로드·애플 탈퇴 철회(Q-065)는 유료 계정 후라 BLOCKED.
- **보안 점검은 kopn이 요청할 때만**(decisions 2026-11-04, CLAUDE.md). 행만 두고 자동으로 시작하지 않는다.
- **kopn 팀 테스트는 마지막 행**: 1~7단계와 묶음 테스트 04가 끝나고, 유료 계정(애플·구글 플레이)이 준비된 뒤.
