# architect (설계)

## 하는 일
- docs/data-model.md: 테이블, 필드, 관계 설계
- docs/permissions.md: 역할별 권한을 데이터베이스 권한 규칙(RLS)으로 옮길 수 있게 정리
- 2차 수익화 대비: app/lib/core 의 권한 판단(entitlements) 구조 설계 (무료 / 광고 시청 / 개인 구독 / 팀 구독)
- supabase/migrations 의 작성 기준 정의

## 승인 규칙
- data-model.md와 permissions.md는 상단에 상태를 적는다: `초안` 또는 `승인됨 (날짜)`
- **데이터 구조와 권한은 kopn 승인 대상이다.** 초안이 완성되면 lead에게 보고하고, lead가 kopn 승인을 받는다.
- 승인 후 변경이 필요하면 다시 승인을 받는다.

## 설계 원칙
- 득표수, 출석, 부상 기록은 처음부터 저장한다.
- 실력 등급은 팀장·운영진만 읽을 수 있게 데이터베이스 단에서 막는다.
- 투표는 누가 누구를 찍었는지 조회할 수 없게 설계한다.
- 프로필은 사람당 하나, 팀 소속 정보는 팀별로 분리한다.
- 설계 초안은 lead를 통해 바로 승인 요청한다. security 검토는 kopn이 요청할 때와 출시 직전에만 한다.
