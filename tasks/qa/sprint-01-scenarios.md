## 읽는 법

- **유형**: 정상 / 경계 / 권한(다른 역할·다른 팀·비로그인 사용자가 시도) / 예외
- **대응**: 아래 완료 기준 코드. 완료 기준에 없는 규칙은 `기준 외(근거)`로 적는다. 결정 기록이 근거면 질문 번호(Q-xxx)를 함께 적는다.
- **기대 동작 미정**: 기획서·결정 기록으로 정답이 정해지지 않은 부분. 자리만 두고 정답을 적지 않았다. lead 확인 전에는 통과·실패를 판정하지 않는다.
- **권한 시나리오는 두 경로로 확인한다**: (1) 앱 화면에서 버튼이 보이지 않는지, (2) 화면을 거치지 않고 Supabase API를 직접 호출해도 서버가 거부하는지 (security.md "화면에서 숨긴 기능이라도 서버에서 권한을 다시 확인한다").
- **SEC = 출시 전 security 점검 대상**: 대응 칸에 SEC가 있는 시나리오는 qa가 기능 확인 때 함께 실행하되, 보안 판정은 출시 직전(또는 kopn 요청 시) security 점검에서 한다 (decisions.md 2026-11-04).
- **BLOCKED**: kopn 답을 기다리는 부분. 그 부분은 실행·판정하지 않는다.
- **이름 글자(Q-034)**: 팀 이름·팀에서 쓸 이름은 한 줄, 이모지·특수문자 허용, 가운데 연속 공백은 하나로 줄인다.
- **글자 수 규칙(Q-012)**: 이 문서의 모든 "n자"는 눈에 보이는 글자 단위(이모지 하나 = 1자, 결합 이모지·국기도 1자), 앞뒤 공백 제외, 가운데 공백은 1자로 센다. 줄바꿈은 입력할 수 없다. 앱과 서버가 같은 기준으로 세야 한다.
- **알림 시나리오**: 알림 발송은 스프린트 02 작업이다. 이 문서의 알림 항목은 "알림 대상이 맞게 정해지는지"까지만 확인하고, 실제 발송은 스프린트 02에서 확인한다.

## 1. 로그인(안드로이드 카카오·구글 / iOS 카카오·구글·애플) + 같은 이메일 안내 + 가입 동의(만 14세·약관·개인정보·부상 정보) (기획서 4장, Q-006-2, Q-007-2, Q-023, Q-028, Q-030, Q-049~Q-053, Q-056, Q-059)

결정: 로그인 방법 하나 = 계정 하나. 계정 연결 기능 없음(Q-007-2, Q-008-2). 같은 이메일이라도 자동으로 합치지 않음(Q-006-2). 애플 로그인은 iOS 앱에만(Q-030), 안드로이드에는 넣지 않고 기기를 바꾼 애플 가입자는 새로 가입(Q-050).
같은 이메일(Q-056, Q-059): 같은 이메일이어도 **모든 로그인 방법으로 새 가입 허용** (Q-045 "새 가입 차단"은 뒤집힘). 가입 전에 "이전에 카카오로 가입한 기록이 있어요. 기존 팀·기록은 카카오로 로그인해야 보여요" 안내 후 [새로 가입] / [기존 방법(카카오)으로 로그인] 선택. 새로 가입한 계정은 기존 계정과 연동 없는 별개 계정. Supabase 같은 이메일 자동 합치기를 끌 수 없으면 다른 서비스 검토(kopn 승인 필요) — 그 결과에 따라 로그인 시나리오 전체를 다시 본다.
가입 동의(docs/consent-texts.md, 로그인 직후·프로필 만들기 전): [필수] 만 14세 이상 / [필수] 이용약관 / [필수] 개인정보 수집·이용 / [선택] 부상 정보 수집·이용(Q-049, 문구 확정 Q-057). 부상 동의는 다른 동의와 분리. 약관·처리방침 동의는 어떤 버전에 언제 동의했는지 기록, 회원 탈퇴 시 함께 삭제(Q-053). 부상 동의는 프로필 설정에서 철회 가능, 철회 즉시 비공개 + 부상 기록 삭제(Q-052).

## 4. 팀 관리: 운영진·위임·탈퇴·내보내기·해체 (기획서 6장, 11장, Q-015, Q-018, Q-022)

기록 보관(Q-058, 2026-11-05): 팀을 떠난 사람(팀 나가기·내보내기)은 남은 기록에서 이름·프로필이 공란으로 보이고(Q-040 대체), 본인의 출석·수상 카운트는 본인에게 남는다. **범위 밖**: 팀별 최근 10경기 상세만 보관·11번째 이전 자동 삭제, 수상·출석 시즌별 영구 카운트, 팀별·사람별 월간 출석 수 보관, 부상 기록 보관 기간은 일정·투표·부상 기능이 생기는 스프린트 02~04에서 다룬다. 못 온 사람 처리(Q-046: 경기 종료 전까지 배치에서 빼면 출석·투표 대상에서 제외, 투표가 열리면 명단 고정, 경기 시작 후 배치 수정은 변경 알림 없음)도 **범위 밖**, 스프린트 03 시나리오에서 다룬다.

알림 대상(Q-022 추가분 포함, notifications.md): 팀원 탈퇴 → 팀장·운영진 / 운영진 지정·해제 → 본인 / 팀장 위임 받음 → 본인 / 내보내기 당함 → 본인. 이 알림들은 조용한 시간 예외가 아니므로 00:00~08:00에는 푸시만 보류 후 08:00 발송하고, 앱 안 알림함에는 바로 쌓인다 (Q-033). 알림 문구에는 관련된 사람 이름이 들어간다 (Q-044). 알림함은 30일 보관 (Q-041).

## 5. 초대 링크·초대 코드·팀 식별코드·팀 검색·가입 신청·승인/거절 (기획서 7장, Q-002, Q-020, Q-021, Q-029, Q-039, Q-042, Q-051, Q-054)

설치 후 이어서 가입은 "링크 페이지에서 초대 코드 복사 → 앱 첫 실행 때 붙여넣기" 방식(유료 딥링크 서비스 없음, Q-002).
초대 링크 규칙(Q-020): 팀당 유효한 링크 1개, 재발급하면 이전 링크 무효, 24시간 안 여러 명 사용 가능, 만료는 신청을 낸 시각 기준, 원본 미저장(다시 복사하려면 재발급). 초대 코드는 링크에 담긴 값과 같고 규칙도 같다 (decisions.md lead 정리). 이미 낸 신청은 그 뒤 재발급돼도 유효 (Q-042), 그 뒤 팀이 모집을 꺼도 유효 (Q-054).
팀 식별코드(Q-029): 초대 코드와 **별개**. 팀마다 영문 대문자+숫자 6자리(0·O·1·I 제외), 팀 찾기 용도. 모집 중일 때만 신청 가능(검색과 같은 규칙). 같은 이름 팀을 구분하는 역할. 소문자로 입력해도 대문자로 인식, 0·O·1·I를 입력하면 "없는 코드예요", 팀원 전체가 볼 수 있음, 한 번 정해지면 변경 불가, 틀린 입력 횟수 제한 없음 (Q-051).
**링크 페이지 호스팅은 추후 지정(Q-039)**: 링크를 열어 웹 페이지를 보는 단계(J-01, J-05, J-12, J-14, J-26의 해당 부분)는 BLOCKED. 초대 코드를 직접 입력해 확인하는 부분은 진행 가능.
