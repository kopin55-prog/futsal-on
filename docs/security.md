# 보안 체크리스트

security 에이전트가 설계 단계, 기능별, 출시 직전에 이 목록으로 점검한다.

## 데이터 분리와 권한
- [ ] 모든 테이블에 권한 규칙(RLS)이 켜져 있다
- [ ] 다른 팀의 일정·명단·투표·배치가 조회되지 않는다
- [ ] 실력 등급은 팀장·운영진만 조회된다 (본인 포함 팀원은 불가)
- [ ] 운영진 지정·해제, 팀원 내보내기, 위임, 해체는 팀장만 가능하다
- [ ] 화면에서 숨긴 기능이라도 서버에서 권한을 다시 확인한다

## 투표
- [ ] 누가 누구에게 투표했는지 어떤 경로로도 조회되지 않는다
- [ ] 득표수는 저장되지만 1차에서는 1위 외에 조회되지 않는다
- [ ] 한 사람이 항목별로 한 표만 행사할 수 있다, 본인에게 투표할 수 없다

## 초대와 가입
- [ ] 초대 링크 값은 추측할 수 없는 무작위 값이다
- [ ] 초대 링크는 발급 후 24시간이 지나면 사용할 수 없다
- [ ] 인원 모집이 꺼진 팀은 검색으로 가입 신청할 수 없다

## 계정
- [ ] 로그인 서비스가 **인증한** 이메일이 같을 때만 같은 계정으로 자동 합쳐진다(Supabase 기본 자동 합치기). 인증되지 않은 이메일이나 다른 이메일은 기존 계정에 붙지 않는다 (Q-063 A, Q-006-2·Q-056 대체)
- [ ] 카카오가 이메일을 "인증 안 됨"으로 넘길 때 기존 계정에 합쳐지지 않는다(별개 계정 또는 로그인 거부, 개발 프로젝트에서 실제 동작 확인) (Q-063)
- [ ] 수동 연결(manual linking)이 Supabase 대시보드에서 꺼져 있고, 앱에 계정 연결·연결 해제 기능이 없다 (Q-063, Q-007-2)
- [ ] 쓰지 않는 로그인 방식(특히 "Email")이 Supabase 대시보드에서 꺼져 있다. 카카오·구글·애플만 켠다 (개발 프로젝트는 2026-11-05 꺼짐 확인, 운영 프로젝트도 확인)
- [ ] 회원 탈퇴 시 계정에 붙은 모든 로그인 방법이 지워지고, 방법마다 외부 서비스 연결 해제(카카오 연결 끊기, 구글·애플 토큰 철회)가 된다 (Q-009, Q-063)

## 개인정보
- [ ] 가입 시 부상 정보 처리 동의(최초 1회 체크박스)를 받고, 동의 기록이 남는다 (Q-028)
- [ ] 수집 항목은 기획서에 정한 최소 범위다
- [ ] 로그에 개인정보와 토큰을 남기지 않는다

## 키와 배포
- [ ] 서비스 키·비밀 키가 앱 코드와 저장소에 없다
- [ ] 앱에는 공개용 키만 들어간다
