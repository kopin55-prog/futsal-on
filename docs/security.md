# 보안 체크리스트

security 에이전트가 설계 단계, 기능별, 출시 직전에 이 목록으로 점검한다.

## 데이터 분리와 권한
- [ ] 모든 테이블에 권한 규칙(RLS)이 켜져 있다
- [ ] 다른 팀의 일정·명단·투표·배치가 조회되지 않는다
- [ ] 실력 등급은 팀장·운영진만 조회된다 (본인 포함 팀원은 불가)
- [ ] 운영진 지정·해제, 팀원 내보내기, 위임, 해체는 팀장만 가능하다
- [ ] 화면에서 숨긴 기능이라도 서버에서 권한을 다시 확인한다

## 투표
- [ ] 누가 누구에게 투표했는지 어떤 경로로도 조회되지 않는다
- [ ] 득표수는 저장되지만 1차에서는 1위 외에 조회되지 않는다
- [ ] 한 사람이 항목별로 한 표만 행사할 수 있다, 본인에게 투표할 수 없다

## 초대와 가입
- [ ] 초대 링크 값은 추측할 수 없는 무작위 값이다
- [ ] 초대 링크는 발급 후 24시간이 지나면 사용할 수 없다
- [ ] 인원 모집이 꺼진 팀은 검색으로 가입 신청할 수 없다

## 계정
- [ ] 이메일이 같아도 계정이 자동 병합되지 않고, 다른 방법으로는 별개 계정으로 가입된다 (Q-006-2, Q-056)

## 개인정보
- [ ] 가입 시 부상 정보 처리 동의(최초 1회 체크박스)를 받고, 동의 기록이 남는다 (Q-028)
- [ ] 수집 항목은 기획서에 정한 최소 범위다
- [ ] 로그에 개인정보와 토큰을 남기지 않는다

## 키와 배포
- [ ] 서비스 키·비밀 키가 앱 코드와 저장소에 없다
- [ ] 앱에는 공개용 키만 들어간다
