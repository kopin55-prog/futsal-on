## 읽는 법

- **유형**: 정상 / 경계 / 권한(다른 역할·다른 팀·비로그인·떠난 사람이 시도) / 예외(재실행·동시 실행·중단)
- **조건 → 동작 → 기대 결과** 순서로 적는다. 시각은 모두 **한국 시간, 서버 시계 기준**(기기 시계를 바꿔도 결과가 같아야 한다).
- **대응**: sprint-02.md "QA 완료 기준" 코드(A-01 등), 작업 번호(1-1 등), 결정 번호(Q-xxx). sprint-01 시나리오에서 옮긴 것은 원래 ID를 함께 적는다.
- **Q-072**: 처음 작성 때 "미정 (Q-072 n번)"으로 두었던 곳은 Q-072 답변(2026-11-05, decisions.md)으로 모두 채웠다. 남은 미정 없음.
- **보고 L-xx**: 결정 기록으로 기대 동작이 정해지지 않아 문서 끝 "lead에게 보고" 목록에 올린 부분. 판정하지 않는다.
- **권한 시나리오는 두 경로로 확인한다**: (1) 앱 화면에 버튼·정보가 없는지, (2) 화면을 거치지 않고 Supabase API(표 직접 읽기·쓰기, 서버 함수 직접 호출)로 시도해도 서버가 거절하는지. 우회 시도는 "API 직접"으로 표시한다.
- **SEC**: 출시 전 security 점검 대상. qa는 기능 확인 때 함께 실행하고 보안 판정은 security 점검에서 한다.
- **실행 시점**: 1~4단계는 Firebase 없이 실행(푸시는 발송 대기열 `notification_outbox`의 send_at·status로 확인). 5단계는 Firebase 준비(0-2·0-3) 후. "04 실행"·"03 실행"은 해당 스프린트에서 실행할 시나리오를 자리만 옮겨 둔 것.

## 테스트 준비물

- 팀 A: 팀장 A0, 운영진 A1·A2, 팀원 A3~A6. 정기 운동일 수 10:00~12:00, 팀 지정 풋살장 있음, 경기 설정 기본값(자동 생성 6일 전 09:00, 마감 2시간 전 Q-066, 미투표 알림 마감 2시간 전 Q-072 1번, 정원 없음)
- 팀 B: 팀장 B0 (다른 팀 역할). 팀원 A3은 팀 B에도 소속시켜 둔다(다른 팀 영향 확인용)
- 팀 C: 정원 시나리오용, 테스트 계정 14명(C0 팀장 + C1~C13). 계정이 부족하면 서버 함수 직접 호출로 응답을 넣는다(응답 넣기 자체도 본인 토큰으로만)
- 소속 팀 없는 로그인 사용자 N1, 비로그인 호출(익명 키만)
- 예약 작업(자동 생성, 미투표 알림, 참여율 처리, 정리, 발송)을 **원하는 시각 기준으로 수동 실행하는 수단**. 개발 DB 확인용 서버 권한 조회 수단(앱 키로는 볼 수 없는 표 확인용, qa가 결과 확인에만 사용)
- 5단계: 안드로이드 휴대폰 2대(또는 같은 휴대폰 2계정), Firebase 개발 프로젝트
