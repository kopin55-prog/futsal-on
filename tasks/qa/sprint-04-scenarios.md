## 읽는 법

- **ID**: sprint-04.md "QA 완료 기준" 코드(I-01 등)를 그대로 쓴다. 한 기준을 여러 경우로 나누면 I-01a, I-01b. kopn 추가 지시는 P-xx(포지션), G-xx(그룹·라이벌 고르기), H-xx(홈 카드 누르면 이동).
- **유형**: 정상 / 경계 / 권한(다른 역할·다른 팀·비로그인·떠난 사람) / 예외
- **확인 방법** (자동 테스트와 휴대폰 확인을 구분한다)
  - **자동-DB**: supabase/tests/sprint04_*.sql 이 이미 확인함 (파일 약칭: s1=step1, s1b=step1b, s2=step2, s3=step3)
  - **자동-앱**: app/test 위젯·단위 테스트가 이미 확인함 (파일 이름 표기)
  - **폰**: 휴대폰(실제 로그인·실제 토큰·실제 푸시·실제 시계)으로만 확인 가능. bundle-test-04.md 에 항목이 있음
  - **폰(보강)**: 자동 테스트가 로직은 확인했지만, 화면 모양·실제 토큰·문구 확인은 폰에서 한 번 더
  - **미구현**: 해당 작업이 아직 "대기"라 지금은 실행 불가
- 자동 테스트 근거는 테스트 파일의 구성(주석·테스트 이름)을 읽어 표시했다. 이번 QA 에서 다시 실행하지는 않았다(lead 확인: DB 18개 ALL PASSED, flutter test 562개 통과, 2026-11-10).
- 시각은 모두 한국 시간, 서버 시계 기준.
- **L-xx**: 기대 동작이 문서로 정해지지 않았거나 문서와 구현이 달라 문서 끝 "lead에게 보고" 목록에 올린 부분. 판정하지 않는다.
- 권한 시나리오는 화면에 없는지 + API 직접 호출도 거절/0건인지 두 경로로 본다.

- 팀 A: 팀장 A0, 운영진 A1, 팀원 A2~A12. 팀 B: 팀장 B0, 팀원 A2도 소속. 팀 C: B0만 소속(다른 팀 확인용).

- 휴대폰 확인용: 안드로이드 휴대폰 1~2대 + 계정 3개 이상 (bundle-test-04.md).
