# 스프린트 01 테스트 시나리오

작성: qa · 2026-11-04 · 근거: 기획서 rev 17 사본(4~7장, 11장), docs/permissions.md, docs/security.md, docs/decisions.md, docs/notifications.md
상태: **초안**. 데이터 구조가 아직 승인되지 않아(data-model.md "초안 미작성") 서버 측 시나리오는 테이블·함수 이름 없이 동작 기준으로만 적었다. 승인 후 구체화한다.

## 읽는 법

- **유형**: 정상 / 경계 / 권한(다른 역할·다른 팀·비로그인 사용자가 시도) / 예외
- **대응**: 아래 완료 기준 코드. 완료 기준에 없는 기획서 규칙은 `기준 외(n장)`으로 적는다.
- **기대 동작 미정**: 기획서·결정 기록으로 정답이 정해지지 않은 부분. 시나리오는 자리만 두고 정답을 적지 않았다. lead 확인 전에는 통과·실패를 판정하지 않는다. 전체 목록은 맨 아래 "기대 동작 미정 목록"에 있다.
- **권한 시나리오는 두 경로로 확인한다**: (1) 앱 화면에서 버튼이 보이지 않는지, (2) 화면을 거치지 않고 Supabase API를 직접 호출해도 서버가 거부하는지 (security.md "화면에서 숨긴 기능이라도 서버에서 권한을 다시 확인한다").

### 테스트 준비물 (공통)

- 테스트 계정: 카카오·애플·구글 계정 각 2개 이상. 그중 하나는 이메일 제공 동의, 하나는 카카오 이메일 미동의, 애플은 "이메일 가리기" 사용 계정 1개 포함
- 팀 A: 팀장 A0, 운영진 A1·A2, 팀원 A3·A4
- 팀 B: 팀장 B0, 운영진 B1, 팀원 B3 (다른 팀 사용자 역할)
- 소속 팀 없는 로그인 사용자 N1, 비로그인 상태(익명 키만 가진 호출)
